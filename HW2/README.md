# ПОС · домашнее задание № 2

Консольное приложение для преподавательской оценки студентов одного курса. Оно ведёт рубрикатор и оценки, рассчитывает итог и выгружает ведомость в CSV.

## Сборка и запуск

Используйте JDK 17–25 и терминал в UTF-8. Gradle Wrapper берёт JDK из `JAVA_HOME` или `PATH`. Приложение компилируется для Java 17.

Из корня репозитория в Windows (PowerShell):

```powershell
chcp 65001
.\gradlew.bat -p HW2 clean build
.\gradlew.bat -p HW2 run --console=plain
```

Из корня репозитория в Linux или macOS:

```sh
./gradlew -p HW2 clean build
./gradlew -p HW2 run --console=plain
```

Команда `clean build` собирает приложение и запускает тесты. Чтобы запустить только тесты, используйте задачу `test` вместо `clean build`. `HW2` собирается отдельно от остальных модулей.

## Пример работы

Введите в консоли приложения:

```text
student | s1 | Анна Петрова
criterion | exam | Экзамен | 10 | 3
criterion | lab | Практика | 20 | 1
grade | s1 | exam | 8
progress | s1
grade | s1 | lab | 10
result | s1
export | results.csv
exit
```

`progress` покажет `80.00%` по одному оценённому критерию. После второй оценки итог составит `72.50%`. В `HW2/results.csv` появится строка `"s1","Анна Петрова",2,2,72.50`. Выгрузка создаёт новый файл в UTF-8. Для повторной выгрузки укажите другое имя файла. Можно передать абсолютный путь.

Для просмотра данных есть `students`, `criteria`, `grades | s1` и `results`. Повторная команда `grade` исправляет оценку, а `cancel | s1 | lab` отменяет её. Команда `help` показывает весь список. Дробные числа можно вводить с точкой или запятой. Рубрикатор, студенты и оценки хранятся в памяти до выхода.

## Доменная модель

- **Курс** (`Course`) — корень агрегата. В его границах находятся студенты, рубрикатор и оценки. Один курс соответствует одной ведомости. Он обеспечивает уникальность ID и проверяет принадлежность студента и критерия перед выставлением оценки.
- **Студент** (`Student`) и **критерий** (`Criterion`) — сущности, которые курс различает по ID. Названия могут совпадать. Максимум и вес критерия строго положительны. Изменение максимума и удаление критериев не предусмотрены в текущих сценариях.
- **Балл** (`Score`) — объект-значение. Баллы `7` и `7.00` равны. Ноль допустим, отрицательное значение отклоняется. Фабрика оценки дополнительно проверяет балл по максимуму критерия.
- **Оценка** (`Evaluation`) — факт выставления балла. Студент определяется коллекцией оценок, которой принадлежит запись. В паре «студент — критерий» хранится одна актуальная оценка. Неудачное исправление оставляет прежнюю оценку.
- **Итог** вычисляет доменный сервис `WeightedResultService`. Он делит сумму `(балл / максимум) × вес` на сумму весов и умножает на 100. Округление до сотых выполняется один раз, по правилу HALF_UP. В полном итоге пропущенные оценки дают нулевой вклад при сохранении их веса. Прогресс использует веса только оценённых критериев. При отсутствии подходящих критериев выводится «нет данных».

## Архитектура

Ports and Adapters. Зависимости направлены как `adapter → application → domain`. Адаптеры также используют доменные типы и реализуют порты внутренних слоёв.

| Пакет | Ответственность |
| --- | --- |
| `pos.domain` | Агрегат, рубрикатор, оценки, инварианты, расчёт и порт `CourseRepository` |
| `pos.application` | Сценарии `Gradebook`, строки отчёта и порт `ResultExporter` |
| `pos.adapter` | Консоль, репозиторий в памяти и запись CSV |
| `pos` | `Main` и `AppConfig` собирают зависимости через Spring `AnnotationConfigApplicationContext` |

## Паттерны GoF

| Группа | Паттерн | Применение |
| --- | --- | --- |
| Порождающий | Фабрика | `Evaluation.create` — единственный способ создать оценку. Курс передаёт найденный в рубрикаторе критерий, и фабрика проверяет верхнюю границу до записи. |
| Структурный | Фасад | `Gradebook` даёт консоли единый интерфейс сценариев и координирует загрузку курса, расчёт и экспорт. |
| Поведенческий | Стратегия | `ScorePolicy` задаёт полный итог и прогресс по оценённым критериям. Доменный сервис использует общий алгоритм взвешивания для обеих стратегий. |

## Тесты

JUnit проверяет инварианты, исправление и отмену оценок, изменение итога при расширении рубрикатора, точное округление и сквозной сценарий от консольных команд до CSV. В сквозном тесте используется граф зависимостей из Spring-конфигурации.
